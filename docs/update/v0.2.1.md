# v0.2.1

## 版本

`0.2.1`

## 发布时间

2026-10-01

## 概述

本版本是一次以修复与构建体验为主的修订版本：一方面让 LeetCode Cloudflare 人机验证真正遵循设置中选择的地区，并在验证窗口中改用站点首页以提高通过率；另一方面新增 macOS Apple Silicon 的本地打包目标，便于在 M 系列 Mac 上直接产出可安装的 DMG。官网页脚同时补充了 GitHub 仓库入口。

## 新功能与变更

- Makefile 新增 `build-macos-m1` 目标：自动检查并安装 `aarch64-apple-darwin` Rust target，交叉编译对应架构的 Go sidecar，并以 Tauri ad-hoc 签名（`APPLE_SIGNING_IDENTITY=-`）打包 macOS 安装包，完成后列出产出的 `.dmg` 与 `.app` 路径；目标架构可通过 `MACOS_ARM_TARGET` 变量覆盖。
- 修复 `make help` 的目标匹配正则，使其同时接受含数字字符的目标名（如 `build-macos-m1`），避免新目标不出现在帮助列表中。
- 官网页脚导航新增 GitHub 仓库链接，新标签页打开并设置 `rel="noopener noreferrer"`，同时补充中英文案映射（`website/src/Website.jsx`）。

## 修复

- Cloudflare 验证窗口按设置中的地区打开：不再硬编码 `cn`，改为读取 `settingsRef.current.leetcode_region`，为空时回退 `cn`，使 Global 站点账号也能走通验证流程（`src/pages/Settings.jsx`、`src-tauri/src/main.rs`）。
- Cloudflare 验证窗口改为打开站点首页而非 `/graphql/` 接口：浏览器已持有有效 `cf_clearance` 时访问接口只会返回 GraphQL 的 JSON 报错，首页可正常显示内容，若被拦截则由 Cloudflare 展示人机验证页。
- 简化 Cloudflare 挑战状态跟踪：移除基于 `sessionStorage` 的“曾出现过挑战”标记，改为仅在检测到挑战页时跳过 Cookie 抓取，页面正常时即可尝试抓取，避免状态残留导致验证后不再回传 Cookie。
- Cloudflare 验证地址解析失败时返回明确的无效地址错误，而非静默打开异常 URL。

## 构建与发布说明

GitHub Actions 预期构建并发布以下桌面安装包：macOS Apple Silicon 与 Intel DMG、Windows x64 MSI 与 NSIS 安装程序，以及 Linux x64 AppImage、DEB 和 RPM。每个安装包都包含对应 target triple 的 Go sidecar。macOS app 使用 ad-hoc identity `-` 签名，不需要 Apple Developer 账号，但不会获得 Apple 公证；首次打开若被 Gatekeeper 拦截，可前往“系统设置 > 隐私与安全性”并选择“仍要打开”。构建状态以本版本对应的 Actions run 为准。
