# v0.2.4

## 版本

`0.2.4`

## 发布时间

2026-10-03

## 概述

本版本修复 AI CLI 助手在桌面端经常无法启动的问题。以 `.app` 形式运行的 GUI 程序不会继承登录 shell 配置的 `PATH`，因此用户明明安装了 Codex 或 Claude Code 等 CLI，AI 对话仍然报“找不到命令”。本版本在 Go sidecar 侧扩展可执行文件查找范围，并允许用户在助手设置中直接填写完整的可执行文件路径。

## 新功能与变更

- 设置页的 CLI 助手新增“CLI 可执行文件路径”输入框（`src/pages/Settings.jsx`）。留空时沿用该 CLI 预设的默认命令，并保留原有的“实际执行命令”预览。
- 新增 `server/service/ai/cli_path.go`，提供统一的 CLI 可执行文件解析与环境构造逻辑：
  - `cliSearchPath` 在原有 `PATH` 之后追加常见安装目录，包含 `/usr/local/bin`、`/usr/bin`、`/bin`，macOS 上的 `/opt/homebrew/bin`，以及用户主目录下的 `bin`、`.local/bin`、`.npm/bin`、`.npm-global/bin`、`.volta/bin`、`.asdf/shims`、`.local/share/mise/shims`，Windows 上额外包含 `%APPDATA%/npm`，并通过 glob 展开 nvm 各 Node 版本目录下的 `bin`。追加时去重且保持原有顺序。
  - `resolveCLIExecutable` 先按绝对路径或含路径分隔符的写法直接查找裸命令之外的显式路径，再依次尝试系统 `PATH` 与扩展路径；全部失败时返回明确的错误提示，说明需要安装该 CLI 或在助手设置中填写可执行文件的完整路径。
  - `cliCommandEnv` 将子进程环境的 `PATH` 改写为扩展查找路径（大小写不敏感匹配已有 `PATH` 键，无则追加），避免 CLI 自身再派生子进程时丢失路径。

## 修复

- 修复 GUI 启动的桌面端找不到已安装 AI CLI 的问题：`ChatStream` 在执行前先解析出可执行文件的完整路径再交给 `exec.CommandContext`，并把扩展后的 `PATH` 传给子进程。此前直接用配置中的命令名执行，在 macOS `.app` 环境下会因缺少登录 shell 的 `PATH` 而失败。

## 构建与发布说明

GitHub Actions 预期构建并发布以下桌面安装包：macOS Apple Silicon 与 Intel DMG、Windows x64 MSI 与 NSIS 安装程序，以及 Linux x64 AppImage、DEB 和 RPM。每个安装包都包含对应 target triple 的 Go sidecar。macOS app 使用 ad-hoc identity `-` 签名，不需要 Apple Developer 账号，但不会获得 Apple 公证；首次打开若被 Gatekeeper 拦截，可前往“系统设置 > 隐私与安全性”并选择“仍要打开”。构建状态以本版本对应的 Actions run 为准。
