# v0.2.6

## 版本

`0.2.6`

## 发布时间

2026-10-05

## 概述

本版本修复了一个会导致 LeetCode 数据同步持续失败的问题。桌面端在合并账号 Cookie 与浏览器验证 Cookie 时，同名 Cookie 只保留首次出现的那一份；于是登录阶段若抓到过期的 Cloudflare Cookie，后续通过浏览器验证拿到的新鲜同名 Cookie 就永远无法生效，请求仍会带着旧值被 Cloudflare 拦截。本版本改为按名称记录位置，让验证阶段抓到的 Cloudflare Cookie 可以替换掉过期的旧值，同时保持 `LEETCODE_SESSION`、`csrftoken` 等账号 Cookie 的原有优先级不变。

此外，本版本将发布流水线使用的 Go 版本从浮动的 `1.26.x` 固定为 `1.26.8`，避免后续重建时因 Go 补丁版本变化而改变构建产物的 TLS 指纹。

## 新功能与变更

- 发布流水线固定构建使用的 Go 版本为 `1.26.8`（`5bbebb0`）。此前 `actions/setup-go` 的 `go-version` 使用浮动的 `1.26.x`，后续重建可能静默切换到新的 Go 补丁版本。由于 Go 1.24 的 TLS ClientHello 指纹会被 LeetCode 前的 Cloudflare 判定为爬虫并返回 403，指纹的意外变化会让已发布的安装包无法同步数据；固定版本号可保证构建可复现。

## 修复

- 验证 Cookie 可覆盖过期的 Cloudflare Cookie（`db0f99c`，`server/config/leetcode.go`）：
  - `mergeCookies` 此前用 `seen` 集合去重，遇到同名 Cookie 直接跳过，导致首次出现的值永久胜出。登录阶段抓到的 Cloudflare Cookie 若已过期，后续浏览器验证抓到的同名 Cookie 无法生效，同步数据时持续遭遇 403。
  - 改为用 `indexes` 记录每个 Cookie 名在结果中的下标：当来自验证阶段（`verification` 为真）且名称以 `cf_` 或 `__cf` 开头时，直接替换该下标上的旧值；其余同名 Cookie 仍然跳过，因此 `LEETCODE_SESSION`、`csrftoken` 等账号 Cookie 的优先级保持不变。
  - 新增 `isCloudflareCookie` 辅助函数判定 Cloudflare Cookie 前缀。

## 构建与发布说明

GitHub Actions 预期构建并发布以下桌面安装包：macOS Apple Silicon 与 Intel DMG、Windows x64 MSI 与 NSIS 安装程序，以及 Linux x64 AppImage、DEB 和 RPM。每个安装包都包含对应 target triple 的 Go sidecar。macOS app 使用 ad-hoc identity `-` 签名，不需要 Apple Developer 账号，但不会获得 Apple 公证；首次打开若被 Gatekeeper 拦截，可前往“系统设置 > 隐私与安全性”并选择“仍要打开”。构建状态以本版本对应的 Actions run 为准。
