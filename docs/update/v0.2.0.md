# v0.2.0

## 版本

`0.2.0`

## 发布时间

2026-10-01

## 概述

本版本围绕两条主线展开：一是新增基于 GitHub Releases 的应用内版本检查与更新日志，让用户可以在设置页直接看到新版本并跳转下载；二是接入 LeetCode Cloudflare 人机验证流程，在 LeetCode 因安全验证拦截请求时提供可自行完成的验证入口，避免账号被误判为登录失效。同时，官网的下载页与更新日志页改为直接读取真实安装包和 GitHub 发布数据。

## 新功能与变更

- 设置页新增 GitHub 版本检查：比较本地版本与最新 Release，展示新版本号、发布时间和更新日志，并提供前往下载与手动刷新入口（`src/utils/releaseCheck.js`）。
- 设置页可查看当前已安装版本对应的更新日志；取不到时给出明确的空状态与错误提示，而非静默失败。
- 桌面端新增 LeetCode Cloudflare 验证流程：新增 `open_leetcode_cloudflare_verification` 命令打开独立验证窗口，并通过 `capture_leetcode_cloudflare_cookies` 捕获验证后的 `cf_clearance` 等 Cookie 与 User-Agent（`src-tauri/src/main.rs`）。
- 新增 `leetcode-cloudflare` 窗口能力配置（`src-tauri/capabilities/leetcode-cloudflare.json`），仅允许 LeetCode 域名回传验证 Cookie。
- 服务端新增 `LeetCodeRequestAuth`，把账号 Cookie 与验证 Cookie 合并后随请求发送，同名 Cookie 以账号 Cookie 优先，并提供默认 User-Agent（`server/config/leetcode.go`）。
- 账号绑定页接入验证流程：当请求被 Cloudflare 拦截时自动打开验证窗口，验证通过后保存凭据并自动重试（`src/pages/Settings.jsx`）。
- 官网下载页改为提供真实安装包，按访问者设备的系统与架构（arm64 / x64）推荐对应产物（`website/src/Website.jsx`）。
- 官网更新日志页改为读取 GitHub Releases，展示已发布版本列表与 Release 正文。
- Tauri CSP 的 `connect-src` 增加 `https://api.github.com`，以支持应用内版本检查。
- 补充版本检查与更新日志相关的中英文界面文案（`src/i18n/locales/settings.js`）。

## 修复

- 区分“登录失效”与“安全验证拦截”：HTTP 401 提示凭证可能失效并建议重新登录或更换 Cookie，HTTP 403 及验证页特征提示为 LeetCode 安全验证拦截，并说明重新登录未必能解决。
- 校准账号连接状态显示：账号资料与刷题统计被验证拦截时显示“请求受限”而非“需检查登录”，避免误导用户反复重新登录。
- 验证窗口已存在时复用而不重复创建，避免并发弹出多个窗口。

## 构建与发布说明

GitHub Actions 预期构建并发布以下桌面安装包：macOS Apple Silicon 与 Intel DMG、Windows x64 MSI 与 NSIS 安装程序，以及 Linux x64 AppImage、DEB 和 RPM。每个安装包都包含对应 target triple 的 Go sidecar。macOS app 使用 ad-hoc identity `-` 签名，不需要 Apple Developer 账号，但不会获得 Apple 公证；首次打开若被 Gatekeeper 拦截，可前往“系统设置 > 隐私与安全性”并选择“仍要打开”。构建状态以本版本对应的 Actions run 为准。
